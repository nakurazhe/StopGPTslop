# StopGPTslop

[English](README.md) | **简体中文**

清除 GPT Image 2 生成图上的那些痕迹——锐度过高、随机光点、边缘不自然、鳞片状纹路——同时保住画面本身。

本工具是专门针对 GPT Image 2 训练的。它处理的是该模型特有的问题，而非通用的 AI 图像瑕疵，因此用在其他生成器的输出上大概不会有效。

```
输入 → FLUX.2-VAE 编码 → z + α · R(z) → FLUX.2-VAE 解码 → 输出
```

`R` 是一个很小的残差网络（0.48M 参数），它预测图像隐空间表示上的一个修正量。`α` 缩放这个修正量，也是你唯一需要调的参数。改动它不涉及任何重新训练。

## 快速开始

用 [uv](https://docs.astral.sh/uv/)，无需手动配置环境：

```bash
git clone https://github.com/nakurazhe/StopGPTslop.git
cd StopGPTslop
uv run webui.py                                  # 网页界面，会自动打开浏览器
uv run modeling.py -i ./images -o ./cleaned      # 批量处理
```

或者用 pip：

```bash
pip install -e .
python webui.py
```

首次运行会从 HuggingFace 下载 VAE（约 320 MB）并缓存。离线环境可以单独下载后用 `--vae /path/to/FLUX.2-VAE` 指定本地目录。

推荐使用 CUDA 显卡；也能跑在 CPU 上（`--device cpu`），耗时约为 10 倍。

### 显卡驱动与 CUDA 版本

锁定的 PyTorch 构建对应 **CUDA 12.6**，需要 NVIDIA 驱动 **525 及以上**。确认显卡确实被用上了：

```bash
uv run python -c "import torch; print(torch.cuda.is_available())"
```

如果你有 NVIDIA 显卡但这里输出 `False`，通常是驱动版本低于该 CUDA 构建。把 `pyproject.toml` 里的 index URL 改成与驱动匹配的版本（`cu118`、`cu124`、`cu128` 等）再执行 `uv sync`。注意这种情况下 PyTorch 会**静默退回 CPU**，所以装完值得查一次。

### 选择性细节清理（实验性网页模式）

默认启用。此后处理仅使用 CPU，通过局部蒙版抑制重复的细小纹理和孤立斑点，
同时保护较大边缘和有方向性的细节。它使用启发式规则，仍可能影响织物、毛孔等真实纹理。

- **微纹理抑制**（默认 0.55）：通过边缘感知邻域减弱细小的不规则纹理簇和重复纹理。
  检测在潜空间清理之后进行，不要求纹理形成完全规则的网格。
- **细小斑点**（0.35）：局部减弱孤立的亮点或暗点。
- **保留微纹理**（0.65）：值越高，保留的原始细节越多；降低时仅在蒙版区域内
  减少绕过 VAE 的原始高频纹理。
- **显示蒙版**：橙色表示可能处理的区域。下载的 PNG 不包含预览蒙版。

关闭**选择性细节清理**即可在相同主强度和微纹理设置下使用旧处理模式。
新清理步骤位于可选超分辨率之前。解码结果会被缓存；关闭超分辨率时，调整 CPU
清理参数不会重复 GPU 推理。不需要额外模型或依赖。命令行批处理保持不变。
请使用自己的图片在 1:1 缩放下评估清理与细节保留的取舍。
频率细节和 CAS 在清理蒙版内减弱，避免再次放大相同的残余纹理。
颗粒仍是独立的可选效果；评估细小伪影清理时请将其设为零。

### 颜色与渐变（实验性 Web UI 后处理）

两个独立的 CPU 滤镜**默认关闭（0）**，保留原有结果。对于存在问题的图像，
建议从 **0.50** 开始，将颗粒设为零并以 1:1 比例检查。

- **色彩杂斑**：在完整分辨率上根据亮度和颜色差异进行平滑，同时使用四分之一
  分辨率的引导图处理约 8–32 像素半径的斑块。相对方向的邻域颜色一致时才修正
  局部颜色或饱和度异常，并保持亮度。强度同时控制修正幅度和允许的颜色差异。
  保护均匀颜色材质及强颜色边界，但真实的孤立色彩点缀仍可能被误判为斑块。
  大范围错误照明、强烈彩边和色彩摩尔纹可能仍然存在。
- **渐变色带**：在低频引导图上进行最大半径 32 像素的多尺度修正，保留原始
  高频残差。强度自适应调整对比度和纹理阈值，允许处理较强阶梯和适度纹理。
  RGB 方差及完整窗口的边缘最大值保护轮廓和细线。
  处理的是色调阶梯，不是物体斜边的锯齿。强色带可能残留；高强度可能使真实的弱轮廓变软。
- **渐变抖动**：默认启用，但仅在去色带实际改变像素的区域生效。
  在舍入前添加不超过半个 8 位码值的稳定单色噪声，与艺术颗粒效果独立。

这些滤镜不依赖选择性细节清理开关。橙色预览蒙版仍然**仅表示微纹理清理**，
不显示颜色或渐变蒙版。新后处理位于可选超分辨率和锐化之后；颜色清理、
去色带和颗粒之间保持 float32，最后仅进行一次 8 位 PNG 量化。
前面的 VAE 合成、细节清理和超分辨率仍保留原有的 8 位边界；
这不是端到端高位深处理，也不支持 16 位导出。

不需要额外权重、依赖或 GPU 推理。调整这些控制会复用包括超分辨率在内的上游缓存。
CPU 时间和内存随分辨率增加；不承诺通用处理速度。命令行保持不变。
代码为独立实现；算法参考
[FFmpeg chromanr](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_chromanr.c)
和 [neo_f3kdb](https://github.com/HomeOfAviSynthPlusEvolution/neo_f3kdb)，
并未捆绑这些插件或复制源代码。请在自己的生成图像上验证后再用于最终输出。

## 命令行

```bash
uv run modeling.py -i INPUT -o OUTPUT             # 单个文件或整个目录
uv run modeling.py -i ./in -o ./out --alpha 0.25  # 更温和
uv run modeling.py -i ./in -o ./out --recursive   # 包含子目录
uv run modeling.py -i ./in -o ./out --side-by-side
```

已有输出的图片会被跳过，所以中断后直接重跑即可继续。用 `--overwrite` 强制重做。完整选项见 `--help`。
递归处理保留输入子目录；输出目录位于输入目录内时，会将其排除。输出文件名冲突或可能覆盖源文件时，会在推理前报错。
读取、处理和保存失败会返回退出码1，其余文件继续处理。保存使用原子替换，
避免将不完整的文件误认为已完成。CLI 和网页都应用 EXIF 方向；动画及多页图片会明确拒绝。

## 强度

| α | 档位 | 效果 |
|---|---|---|
| 0.25 | 保守 | 细节基本不动，轻度清理 |
| **0.5** | **平衡（默认）** | **较好的折中** |
| 0.75 | 强力 | 明显更干净，伴随一定纹理损失 |
| 1.0 | 激进 | 清理最强，可见的变软与颗粒感 |
| 0 | — | 不清理；用作参照 |

**怎么选**：从 0.5 起步。仍有残留就往上调；画面发软或纹理开始糊掉就往下调。在你觉得合适的取值中，选最低的那个。

有一点值得知道：**不要用"痕迹是否彻底消失"来判断效果。** 即便只清掉一部分，观感通常也已大幅改善；而为了追最后那点残留把强度推高，代价是真实细节。请按画面看起来如何来判断，而不是按去掉了多少。

## 性能

耗时取决于设备、分辨率、启用的滤镜和缓存状态。上游基础流程的计时不代表扩展网页流程：新图片通常需要一次 VAE 编码、两次解码（基线与修正）以及 CPU 后处理。颜色、渐变清理和可选超分会增加耗时；缓存命中时可跳过前序步骤。

CPU 清理使用减少临时分配的 float64 方框求和，以及可分离的精确 5×5 最小值/最大值滤波。保留原有运算、舍入和边界规则，不添加依赖或 GPU 计算。回归测试与旧实现逐值比较蒙版、后处理及像素。实际提速取决于图片和设置，不通过降低分辨率或减弱清理来加速。

本地验证环境：Windows、Ryzen 5 5600G / RTX 4060 8 GB、PyTorch 2.13.0+cu126、bf16、VAE 分块、未编译。预热后，每个版本各运行两次且不使用图片缓存，平均耗时：1672×941 为 **8.80 → 7.46 秒**，712×900 为 **3.16 → 2.63 秒**。设置：alpha 1、micro 0.55、spots 0.35、preserve 0.65；关闭超分、颜色/渐变滤镜、锐化、颗粒和蒙版。计时包含处理及 PNG 编码，不含模型启动或浏览器传输。PNG 字节完全一致；PyTorch CUDA 峰值已分配显存未变（分别为 2692 / 1946 MiB）。这只是两个本地样例，不是普遍吞吐量保证，也不代表总内存/显存占用。

CLI 仅在数量达到 `--compile-min` 时自动编译，可用 `--compile on` 强制启用。网页默认编译，可用 `--no-compile` 关闭。编译需要兼容后端且有预热开销；本地 Windows 基准环境未启用编译。仍可使用 VAE 分块来限制显存占用。

## 已知局限

**部分细节无法挽回。** 这些痕迹与真实纹理处在同一尺度上，且在空间上互相重叠，因此清除它们总要付出一些真实细节的代价。在少部分图像上，两者耦合得足够紧，以至于没有令人满意的强度取值：清理够了就会明显变软，想保住细节就得留下痕迹。这是方法本身的性质，调参解决不了。

**最佳强度因图而异。** 同样是从 0.75 降到 0.5，有的图几乎没变化，有的图差别很大。目前没有可靠的自动选取办法，所以对一批相似的图，值得先用 `--side-by-side` 试几个取值。

**每张图都会过一遍 VAE。** 影响非常小，但严格来说输出在未改动区域也不是输入的逐像素副本。
